## Security incident and cleanup

Before the final login fix, an automated A login clicked while the form was not hydrated. Its native GET placed the actual password in the URL and one encoded test failure output. That URL may have reached hosting request logs. The local failed-test artifact was removed, subsequent automation output redacts raw and encoded credentials, and hosted traces/videos/screenshots remain disabled. The password was not copied into this report. The fix passed server-rendered disabled-control and hydrated login tests, then deployed to staging; owner rotation was required to retire the exposed value.

The owner subsequently confirmed completion of the final rotation. The real UI showed `password=updated` and normal Auth login with the saved credential succeeded. The retired plaintext had already been overwritten before the comparison capture, so a separate negative login using that exact previous password is **not claimed**. No new password was entered by the agent. Server-side recovery expiry was independently confirmed as one hour; [Supabase documentation](https://supabase.com/docs/guides/auth/auth-email-passwordless) confirms that Email OTP Expiration also governs password recovery links. This is an inspected server setting, not a claim that a fresh real email was held for a full hour during the test.

Final cleanup independently verified both original active OWNER memberships, absence of B's disposable A clinic/organization grants, restored synthetic doctor association, restored original JWT lifetime and absence of the local temporary bypass secret. Vercel revocation was acknowledged after every run. Only a revoked short-lived test session was used for expiry; its local token/cookie fixture was removed after the passing test. No production data, real patient contact, administrative password reset or auto-confirm operation was used.
